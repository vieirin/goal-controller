# GODA-MDP: SA-BSN (goalModel.txt)

**What it exercises:** the goal model of the self-adaptive Body Sensor Network, as its runtime consumes it: `#` (parallel) on a goal (`G2 [G3#G4]`) and a 6-operand `#` chain on a task (`T1:Monitor vital signs [T1.1#…#T1.6]`, no space after the colon), two `T1` tasks under different goals (scoped ids `G3_T1_1`…`G3_T1_6`, `G4_T1`), and the two one-line formulas the running system loads.

- **Source:** [lesunb/bsn](https://github.com/lesunb/bsn) at commit `f939d3c8d5fd32c84ab2dbc38d6af9e50da315d9`, `src/sa-bsn/knowledge_repository/resource/models/`. `goalModel.txt` is copied unchanged (including `T1.5`'s `Unknown_sensor`, upstream's). `reference/` holds upstream's `reliability.formula` and `cost.formula` and the eight files of `param.zip`, unzipped.
- **Licence:** MIT, © 2021 Ricardo Caldas (the repository's `LICENSE`).
- **The knowledge repository:** `src/sa-bsn/knowledge_repository/resource/models/{goalModel.txt, reliability.formula, cost.formula, param.zip}`, and `resource/logs/` for what the system records at run time.
- **What the runtime reads:** the two `.formula` files, not the JSON model. `DataAccess::fetch_formula` reads each file's first line and serves it over the data-access service; the adaptation engines (`ReliabilityEngine`, `CostEngine`) compile it with Lepton and evaluate it live over the terms `CTX_`, `F_`, `R_` (reliability) and `CTX_`, `W_` (cost), finding the components by those prefixes; `simulation/analyzer/Analyzer.py` reads the same files. `libbsn/goalmodel` (a goal-tree library with its own tests) is not used by the system. See goal-controller #93.
- **Generator version:** `cc808b6`. `project.json` sets `options.variant` to it and `options.runtimeFormulas` to `true`. With these options, generating writes `reliability.formula` and `cost.formula` byte for byte as in `reference/`, with no trailing newline (#94). The July 2019 generator (`5305bc1`) rejects this model, as upstream's does: it reads `[G3#G4]` as a decision between operands, and G3 and G4 have no context.
- **`param.zip`:** it was not made from this revision of the model. Its formulas are OR-shaped over T1's leaves and AND over G3 and G4. `cc808b6` reproduces all eight files byte for byte from the model with `T1 [DM(T1.1,…,T1.6)]`, T1 OR-refined, and no annotation on G2 (#93).
