# ACME Water: Night (CAIRIS)

ACME Water, the CAIRIS exemplar of a water company's SCADA (its telemetry, ICT and plant, by day and by night), environment **Night**, as lib's CAIRIS importer reads it (goal-controller#192): one KAOS model per environment (D2).

Source: `examples/exemplars/ACME_Water/ACME_Water.xml` in [cairis-platform/cairis](https://github.com/cairis-platform/cairis) at `44cc57d` (Apache 2.0; the file's licence header is kept in lib's copy, `packages/lib/test/importers/fixtures/cairis/ACME_Water.xml`, with CAIRIS's LICENSE). See S. Faily, *Designing Usable and Secure Software with IRIS and CAIRIS*, Springer 2018.

- `cairis-acme-water-night.txt`: the model, the file read for this environment. It has 4 goals, 3 requirements, 1 domain property, 6 agents (CAIRIS's roles), with 3 goal refinements, 1 responsibility assignments. It opens in kaosprop's mode. There is no CAIRIS writer (D4 of #192), so the file is the source and the model is its JSON.
- Values are CAIRIS's, verbatim (D1): a goal's category is its `Type` and its priority its `Priority`, an obstacle's category its `Category`, a domain property's type its `Kind`. The model records the `cairis` vocabulary profile (`diagram.customProperties.vocabulary`), so these values are checked against CAIRIS's enumerations (`goals.dtd`), not the `kaos` dialect's. Without the profile, nearly every goal, obstacle and domain property would be a Problem: `High`, not `high`; `Vulnerability`, not one of TSE'00's five.
- A requirement is a leaf goal (D3), with CAIRIS's `type` and `priority` as `RequirementType` and `RequirementPriority`. It is assigned to the role a manual association names. Requirements, domain properties and roles belong to the project, not to an environment: each is in the environments whose associations (or, for a requirement, whose asset or environment) situate it, and in every environment when nothing does.
- Nothing is left out silently: 2 association(s) with no KAOS link (a task, a use case, a vulnerability, a response, a role dependency) are kept as written in the diagram's `cairisUnsupported`, and the import says each. The rest of the file (assets, threats, vulnerabilities, risks, personas, use cases, countermeasures, …) is counted by the import, not read.
- **No oracle.** The file gives this environment's obstacles no probability (or it has no obstacles), so CAIRIS's propagation over it is all 0 and is not an oracle. kaosprop runs; its values are the seed's own.
