# GODA-MDP: a stress test of the engine framework

GODA-MDP ([lesunb/pistarGODA-MDP](https://github.com/lesunb/pistarGODA-MDP),
Solano et al., SEAMS 2019) generates a PRISM MDP, its PCTL properties and
parametric reliability and cost formulas from a piStar goal model. It is a
lab dialect and EDGE's ancestor. It ships seven example models with their
reference outputs, which gives an oracle. It was added as the fifth engine
(goal-controller#32), following [adding-an-engine.md](adding-an-engine.md).
This page records:

- what GODA reads;
- what fit as it was;
- where the framework had to grow;
- the decisions and the divergences from upstream;
- what is still open.

The work is organised in goal-controller#34. Its decisions are numbered
there (D1 to D16), and this page cites them.

## What GODA reads

The reference is upstream's Java at `c8519f70`, and at the older commits its
outputs were generated with (see [The generator version](#the-generator-version)).
The relevant files are `integration/Controller.java` (the piStar reader),
`generator/goda/producer/RTGoreProducer.java`, `generator/goda/writer/` and
`generator/goda/producer/PARAMProducer.java`. The grammars are in
`src/main/antlr4/br/unb/cic/`.

- **Elements.** Goals `G1` and tasks `T1.1`, in actors.
  - A task's id is scoped by its nearest goal: GODA names it `G3_T1_1`, so
    `T1.1` may appear under `G3` and under `G4` (BSN does).
  - Ids are `T1`, `T1.11`, `T1.411`, `T1.X`, `T1.1X`, `TX`. An `X` is an
    unknown, optional element (Incompleteness).
  - Resources are read and left out (TAS draws some without ids).
- **Links.** AND and OR refinement links. A goal refined by tasks is
  means-end; a task's AND/OR links decompose it.
- **Properties.**
  - `selected: true` marks the goal generated from, and so its actor.
  - `creationProperty` is a context condition (CtxRegex.g4): `assertion
    condition` or `assertion trigger`, then a condition with `< <= > >= =
    != & |`, parentheses, variables, and integers, decimals and booleans.
    `%` separates several.
- **The bracket in an element's text** depends on whether the element is a
  leaf (`RTGoreProducer.java:254-257`):
  - on a refined element it is the RT regex (RTRegex.g4). The MDP generator
    reads decision making only, `DM(T1.1,T1.2,…)`, with any number of
    operands;
  - on a leaf it is the cost (CostRegex.g4): `W = 0.1`, `W = 0.1x` or
    `W = x`;
  - spaces inside the bracket are removed before it is read
    (`removeBlankSpaceInBrackets`). Fragmented.txt writes `D M(T1.11,T1.1 2,…)`.
- **Output**, per selected actor:
  - `<Actor>.nm`, the MDP. It has one module per leaf task, sequenced by
    time slots (`next_n` actions), a formula per goal, the `success` label
    and a `cost` reward;
  - `ReachabilityMax.pctl`, `ReachabilityMin.pctl`, `CostMax.pctl`,
    `CostMin.pctl`;
  - `reliability.out` and `cost.out`, the parametric formulas;
  - `eval_formula.sh`, which evaluates a formula at default parameter values.

## The engine

`packages/lib/src/engines/goda/`:

| File | What it is |
| --- | --- |
| `definition.ts` | The dialect: kinds and prefixes, `DM`, `leafBracket: 'cost'`, `whitespace: 'ignore'`, `idScope: 'ancestorGoal'`, the two properties |
| `checks.ts` | `goda.goal.selected`: one goal is selected, across the model |
| `mapper.ts`, `types.ts` | Each element's text as written (GODA names and tells apart elements by it), its contexts, its RT regex or its cost |
| `template/containers.ts` | RTGoreProducer: the goal and plan containers and their time slots |
| `template/prism.ts` | PrismWriter: the MDP and `eval_formula.sh` |
| `template/formulas.ts` | PARAMProducer: `reliability.out` and `cost.out` |
| `template/templates.ts` | The generator's templates, byte for byte |
| `template/variants.ts` | A generator version as a strategy: its templates, containers, guards and formulas (D14) |
| `template/index.ts` | `godaOutput(model, { modelName, variant })` |
| `formula.ts` | The formulas as numbers: `compileFormula`, `evaluate`, `evalFormulaValues`, `compareFormulas`, shared with the stress test (#35) |

`godaOutput` takes goal-tree's validated model (`Model.parse(text)`), not
the tree. GODA names the MDP after the actor that holds the selected goal,
and the tree doesn't keep actors (D16). It returns eight files, the MDP
first and primary (goal-controller#33): ids `model`, `reachability-max`,
`reachability-min`, `cost-max`, `cost-min`, `reliability`, `cost` and
`evaluate`. Each file's bytes are what upstream's `PrintWriter` writes,
including `println`'s trailing newline and the CRLF line ends of the leaf
template.

## The generator version

The references were not all generated by one version of the generator, and
neither version is the pinned commit (D10):

- `AND`, `OR`, `DM` and `Incompleteness` were committed in `cc808b6`
  (2019-01-29). Each task has a frequency parameter (`const double F_x;`,
  `F_x : (s'=1) + (1 - F_x) : (s'=3)`), and the formulas multiply by it.
- `5848a7a` (2019-04-17) removed the frequency.
- `BSN`, `TAS` and `Fragmented` were (re)generated in `5305bc1`
  (2019-07-10), without it, and with the guard conditions of `9a993f8`.

So `godaOutput` takes a `variant`: `cc808b6` (the default, implemented) or
`5305bc1` (#38 to #40). A variant is a strategy object, `GodaGenerator`
(D14). It has the templates, how the containers and their time slots are
built (the sibling order among them), the guards a leaf's start is written
with, and how the formulas are composed. Adding a version adds one object
to `GODA_GENERATORS`. `GODA_VARIANTS` lists both versions, and
`GODA_IMPLEMENTED_VARIANTS` lists those there are.

## The formulas (D11)

Upstream composes the formulas by string substitution over the containers
(`composeNodeForm`, `getNodeForm`, `SymbolicParamAndGenerator`). It asks the
PARAM binary only for a leaf's reliability. A leaf's model is fixed: it
starts with `F` or is skipped, then succeeds with `R`. So its reachability
is `F_x*R_x` (`R_x` without the frequency). The engine composes the
formulas in TypeScript, with no external tool, and stays usable in the
browser.

The clean-ups that follow are ported as they are, with Java's `split` and
`replaceAll` semantics, because they change what the cost formula computes:

- `replaceReliabilites` puts a child's reliability in place of its `R_`;
- `cleanMultipleContexts` writes a factor repeated in a product once.

Equivalence with a reference is numeric (D3). `compareFormulas` evaluates
both formulas at the values of `eval_formula.sh` and at 100 seeded random
points, and they must agree within 1e-9. On a model of our own
(`examples/goda/LabResults.txt`), the tests check the formulas against the
closed forms of its tree.

## Proof: AND and OR

With the upstream models fetched (`node scripts/goda-stress/fetch.cjs` puts
them in the gitignored `.cache/goda/<commit>/`), AND's and OR's eight
files are **byte for byte** the references. Their formulas also agree at
101 points. `packages/lib/test/engines/goda/goda.test.ts` checks both, and
skips when the cache is empty. The upstream repository has no licence, so
its models are fetched, not committed (D1). The other five models are the
stress test's (#35) and their issues' (#36 to #40).

## What fit as it was

- **The definition.** Kinds with id prefixes, properties with value types,
  a call construct in the notation (MutRoSe's `FALLBACK` made calls a
  form), and a named check.
- **Goal-tree's reading.** The links, the means-end tasks under a goal and
  the AND/OR decomposition of tasks. The mapper hands the template each
  element's text, so it builds GODA's own containers from the tree.
- **Several outputs per model.** goal-controller#33 had just made it a
  framework capability: GODA's eight files are tabs in the workbench, a
  zip, and a project's `out/`.
- **Everything the UI derives from a definition.** The inspector, the
  Notation view, lint, completion and the language server worked
  unchanged. The wiring is the ~12 edits of the guide; GODA has no options.

## Where the framework had to grow

| What GODA needed | What changed |
| --- | --- |
| `DM(…)` with any number of operands | A call's arity can be a minimum (`DM: { arity: { min: 2 } }`). The validator says ``\`DM\` takes at least 2 operands, not 1``. |
| A leaf's bracket as its cost | The grammar's element line reads `[W = …]` as a `Cost` (constant, variable, or both). GoalLexer reads it when a bracket starts with `W =`. A dialect sets `notation.leafBracket: 'cost'`. The validator reports a cost on a refined element, a notation on such a leaf, and a cost in a dialect without them. `parseElementLine` gives `cost`. |
| Ids `T1.411`, `T1.X`, `TX` | `T1.411` and `T1.X` already read. `GX` and `TX` were WORD for two letters, a name (RTRegex.g4's divergence, documented): the lexer splits such a WORD into its prefix and `X` where an id may be. The ANTLR parity test names it. |
| BSN's `T1.1` under two goals | `idScope: 'ancestorGoal'` on a definition: the validator reports a repeated id only under the same goal. |
| Fragmented's `D M(T1.1 2)` | `notation.whitespace: 'ignore'`: the reader and the editors read a line without the spaces in its bracket, and map every span back to the line as written. `parseElementLineIn(dialect, text)`. |
| Context conditions with a prefix and decimals | The `assertion` type gained `prefixes` (`assertion condition`, `assertion trigger`) and `decimals`. One general type, not a GODA one. |
| A task's bracket in its mapper | `mapTaskProps` gets the task's text, as `mapGoalProps` did. |
| An engine named after the model's actor | `godaOutput` takes the validated model (D16). |

Every change kept the other engines byte for byte. `pnpm snapshot:language`
gives the same notation documents and outputs for edge, edgeV2, SLEEC,
MutRoSe and piStar-ext. It now also writes GODA's (`notation/goda__…`,
`goda/`).

## Divergences from upstream

- **A leaf's module name.** Upstream strips an RT regex's bracket from a
  module's name, but not a cost's. A leaf with a cost would be named
  `G1_T1_1_Task[W=0_1]`, which PRISM doesn't read. The engine strips it. No
  reference has a cost bracket.
- **Contexts, decision making, unknown elements.** Their PRISM patterns
  (`pattern_ctx_*`, `pattern_nondeterminism`, `pattern_opt_*`) are each
  model's work. The base throws `GodaUnsupported` with the issue: DM #36,
  `X` #37, contexts #36 and #38. RT operators other than `DM` are not
  enabled; the editors report them.
- **One selected goal.** Upstream generates every actor with a selected goal
  and writes the formulas of the last. The engine requires exactly one
  selected goal (the check reports a second one in the editors).

## Still open

- **The editors key elements by id.** A repeated `T1.1` (BSN) is valid in
  the language, but goal-tree's view keeps the first element of an id, so
  the second one has no Notation line, trace or selection of its own (#40).
- **Upstream's quirks not reached by AND and OR.** Elements with the same
  text share one container. A goal's means-end tasks are read once per
  incoming link. HashMap orders the context comments and the eval script's
  lines (D15). The model issues meet them.
- **`eval_formula.sh` runs `bc`.** The tests evaluate the formulas in
  TypeScript (`formula.ts`); the script is written for parity with upstream.
- **Seed projects** (`examples/projects/goda-*`) wait for the upstream
  licence (#32 item 14).
